Player Onboarding

During registration, a new player can go through an onboarding flow. The onboarding scenario is determined by a unique onboarding link. Partner-based registration scenarios are also supported, including special links for automatic promo code application and preselected bonuses. If no dedicated scenario is configured for a user, the standard «organic» flow is used as the default website registration flow.

Onboarding scenarios (one «organic» flow and additional scenarios for countries and partners) are configured in the BackOffice within the «Onboarding» section. The administrator can configure:

  1. Basic flow parameters: title, description, and the «Organic onboarding» flag, as well as onboarding link generation with domain selection and promo code support.

  2. Countries for which the registration scenario will be available, as well as partner configuration for the use of partner onboarding links.

  3. Onboarding flow steps. The following steps can be configured for the onboarding flow:

    1. Bonus selection. The player is shown bonuses available for the selected flow. The user can choose a bonus, continue registration without a bonus, or use a promo code automatically passed through the onboarding link.

    2. Credentials entry. The player can register using email, phone number, or both methods simultaneously - depending on the flow configuration. Registration through social networks is also supported, as well as verification settings, SMS validation, and display of entered rules and registration terms with support for multiple languages.

    3. Personal data entry. The player fills in additional personal information configured for the flow: first name, last name, date of birth, gender, country (from the list of countries available for the current flow), address, and other fields. All displayed fields are mandatory.

    4. Redirect configuration. If the step is enabled, after registration the player is automatically redirected to the deposit page. If the step is disabled, the user is redirected to the website homepage after registration.

Onboarding flows can be cloned and archived to simplify management of different registration scenarios. Cloning allows administrators to quickly create new onboarding flows based on existing configurations - for example, for specific partners, GEOs, or bonus offers. Archiving allows outdated scenarios to be removed from active use.

Additionally, the «Onboarding» section includes search and filtering functionality for onboarding flows, as well as configuration of visible table columns for easier management.

User Interface

Redesign of the Website Header and Left Sidebar Menu

The website header and left sidebar menu have been redesigned to improve navigation and enhance user interaction with the platform’s main sections. The following changes have been implemented:

  • A search icon has been added to the website header, opening the game search section.

  • The sidebar menu structure has been updated, including expandable «Casino» and «Sport» sections with dedicated subsections.

  • When navigating to the game search section from the sidebar menu, the «Explorer» section with game categories is displayed.

  • For unauthorized users, access to sections available only to authorized players is accompanied by a registration or login prompt.

User Interface

Optimization of Winnings Processing

Optimization has been carried out for processing gaming operations related to winnings calculation and bet result handling. As part of the improvements, performance has been enhanced and processing time for the corresponding gaming scenarios has been reduced.

🪄 Payments-analytics

Backend Platform Improvements

The server-side part of the platform has been updated to improve the stability of user scenarios and payment operations. As part of the improvements:

  • payment and transaction processing has been optimized to reduce the risk of errors and blocking under high load;

  • authorization and processing of requests related to the user profile have been accelerated;

  • automated test coverage for payment operations and payment methods has been significantly expanded to improve the safety and predictability of future changes in this area.

Frontend Platform Improvements

A number of technical improvements have been implemented for the frontend part of the platform. As part of the update:

  • a centralized feature flag management mechanism has been implemented to simplify enabling and disabling functionality, as well as to avoid duplication of logic;

  • interface buttons have been unified under a single standard, including full documentation, display variations, and tests. The updated component will serve as the foundation for a unified development standard for other platform UI components (Contributing Guide);

  • a new integration with the Allure/MCP testing system has been implemented. Existing autotests were updated and new tests and test cases were added, including scenarios for the updated registration flow and wallet. Work with test cases and regression test automation has also been optimized, including the use of AI based on Allure cases, improving quality transparency and regression execution speed.

Preparation for Upcoming Features

As part of the technical sprint, development of new functionality has been started, with releases planned for upcoming sprints.

Balance Logic Rules

Development has started for balance logic rules functionality used to manage fund deduction and crediting during bonus wagering. Work on the functionality will continue in the next sprint, after which it will be prepared for release.

Player Rewards Management Interface Update

Implementation of an updated interface for player rewards management has been started. As part of the update, the rewards section button in the website header, the bonuses page, as well as player campaign and reward cards are being redesigned. Development will continue in the next sprint, after which the updated interface is expected to be released.
