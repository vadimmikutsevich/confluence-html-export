# Локальный интерфейс

React + Vite на фронтенде, Fastify на сервере. Сервер вызывает существующие workflows;
CLI остаётся доступным через `npm run c2b`.

## Запуск

Из корня репозитория:

```sh
npm install
npm run web
```

Откройте **http://127.0.0.1:3000**. Команда собирает интерфейс и запускает сервер.
Токены берутся из `.env` в корне репозитория. В браузер они не передаются.
Используются те же переменные, что для CLI:

```dotenv
CONFLUENCE_BASE=https://company.atlassian.net/wiki
CONFLUENCE_USER=you@company.com
CONFLUENCE_TOKEN=...
BOOKSTACK_BASE=https://book.example.com
BOOKSTACK_TOKEN_ID=...
BOOKSTACK_TOKEN_SECRET=...
```

После изменения `.env` перезапустите сервер. Для другого порта задайте `WEB_PORT`.
Сервер слушает только `127.0.0.1`.

## Работа

1. Вставьте ссылки или ID документов — по одному на строку. Повторы удаляются по ID.
2. Выберите режим: HTML, синхронизация или создание новых страниц.
3. Нажмите «Проверить документы». Проверяются параметры, чтение исходных документов
   и доступ к BookStack, если он нужен. Проверка не выполняет запись.
4. Проверьте сводку и нажмите «Запустить перенос».

Предварительная проверка хранит только параметры запуска. При запуске документы
загружаются заново; HTML, полученный во время проверки, не используется.
Проверка действительна 15 минут и сбрасывается при изменении параметров формы.
Верхних ограничений интерфейса на число документов, глубину рекурсии,
параллельность и размер изображения нет. Значение лимита изображения `0`
отключает ограничение размера, как в CLI. При включённой рекурсии глубина `0`
обрабатывается как `1`, согласно исходному поведению CLI.

Синхронизация использует существующий `bookstack-config.yml` в корне репозитория.
Создание новых страниц позволяет выбрать книгу/главу или указать имя книги.
Рекурсивный обход доступен для HTML и синхронизации. Несколько исходных документов
обрабатываются общей очередью экспорта и общей картой якорей.

Пока обнаруживаются связанные страницы, показывается количество загруженных
документов. После определения объёма синхронизации отображается процент выполнения
этого этапа. Прогресс изображений и журнал передаются через SSE.

«Остановить» завершает текущую страницу и останавливает обработку перед следующей.
Это не откат уже выполненных изменений. Автоматическая очистка галереи **сохранена**:
как и в CLI, старые изображения страницы удаляются перед загрузкой новых.

Обновление вкладки не прерывает задачу. Состояние и последние 300 сообщений
хранятся в памяти сервера; после его перезапуска история не восстанавливается.
Одновременно выполняется одна задача. Результаты HTML сохраняются в
`confluence-export/<id задачи>/` и доступны для скачивания из интерфейса.
Результаты последних 20 задач доступны, пока сервер работает; файлы сохраняются
и после удаления задачи из истории.

## Разработка

В двух терминалах из корня проекта:

```sh
npm run web:server
npm run web:dev
```

Откройте **http://127.0.0.1:5173**. Vite проксирует `/api` в Fastify; браузер
не обращается напрямую к Confluence или BookStack. В обычном запуске Fastify
отдаёт и сборку React, и API с одного адреса.

```text
web/
  client/
    main.jsx           # Экран, проверка и запуск, подписка на задачу
    TransferForm.jsx   # Документы, режимы и параметры
    JobPanel.jsx       # Прогресс, журнал, результаты
    api.js             # Запросы к локальному API
    styles.css
  server/
    index.cjs          # Запуск и завершение локального сервера
    app.cjs            # Fastify-маршруты, SSE, файлы
    config.cjs         # Валидация веб-ввода и серверные настройки
    jobs.cjs           # Проверки, задачи, состояние и события
  vite.config.mjs
  dist/                # Сборка, не хранится в Git
```
