# Confluence → BookStack (CLI)

CLI утилита для выгрузки страниц Confluence в HTML и (опционально) импорта в BookStack:

- Забирает HTML страницы из Confluence через `body.export_view` (экспортный HTML).
- При импорте в BookStack скачивает картинки, загружает их в BookStack image gallery и подставляет BookStack URL в HTML.
- Умеет **сохранять файл по title** и **рекурсивно выгружать связанные страницы** (по ссылкам `/pages/<id>`).

## Структура кода

Точка входа `cli.cjs` загружает настройки, создаёт API-клиенты и запускает нужный сценарий.

```text
cli/options.cjs          — объявления CLI-флагов
config/                 — загрузка настроек, проверка параметров, карта страниц
clients/                — HTTP, авторизация, Confluence и BookStack API
workflows/              — экспорт, синхронизация, импорт страницы, перенос изображений
html/                   — преобразование HTML, ссылок, якорей и изображений
output/                 — имена файлов и сохранение HTML
shared/                 — общие функции для URL и метаданных изображений
```

Сетевые запросы выполняются только внутри `clients/`. HTML-функции получают готовые
данные; загрузку заголовков страниц координирует `workflows/prepare-page.cjs`.
Список страниц BookStack кэшируется в клиенте на время запуска для поиска по URL.

Настройки собираются и проверяются до начала экспорта. Флаги имеют приоритет над
переменными окружения; базовый URL Confluence также может выводиться из `--page`,
а BookStack — из карты страниц при синхронизации. `BOOKSTACK_BASE` поддерживается
как при синхронизации, так и при создании страницы. При включённой рекурсии `--max-depth 0` обрабатывается как `1`, как в исходном CLI.
Для выгрузки только исходной страницы отключите `--recursive`. Нулевой или отрицательный `--concurrency` и отрицательные лимиты
отклоняются до выполнения запросов.

Карта `bookstack-config.yml` остаётся в корне проекта, результаты — в каталоге
`--out-dir`. Имена CLI-флагов и команда `npm run c2b` сохранены.

## Установка

Локальный интерфейс: `npm run web`, затем откройте `http://127.0.0.1:3000`.
Подробности запуска и разработки — в [web/README.md](web/README.md).

Из корня проекта:

```bash
npm i
```

## Быстрый старт

### 1) Переменные окружения

PowerShell:

```powershell
$env:CONFLUENCE_USER="you@company.com"
$env:CONFLUENCE_TOKEN="CONFLUENCE_API_TOKEN"

$env:BOOKSTACK_TOKEN_ID="BOOKSTACK_TOKEN_ID"
$env:BOOKSTACK_TOKEN_SECRET="BOOKSTACK_TOKEN_SECRET"
```

Альтернатива: положить секреты в локальный `.env` (файл игнорируется):

- Скопируйте `.env.example` → `.env`
- Заполните значения

Если вы будете передавать **только** pageId (число), то ещё нужно:

```powershell
$env:CONFLUENCE_BASE="https://gambchamp.atlassian.net/wiki"
```

### 2) Запуск

Выгрузить HTML-фрагмент в файл (имя по title, папка `confluence-export` по умолчанию):

```bash
npm run c2b -- ^
  --page "https://gambchamp.atlassian.net/wiki/spaces/BP/pages/178684038" ^
  --dry-run
```

Выгрузить в конкретный файл:

```bash
npm run c2b -- ^
  --page "https://gambchamp.atlassian.net/wiki/spaces/BP/pages/178684038" ^
  --dry-run ^
  --out ".\\out.html"
```

Рекурсивная выгрузка связанных Confluence-страниц (1 уровень ссылок):

```bash
npm run c2b -- ^
  --page "https://gambchamp.atlassian.net/wiki/spaces/BP/pages/178684038" ^
  --dry-run ^
  --recursive ^
  --max-depth 1
```

**Синхронизация с BookStack** (экспорт + обновление страниц по конфигу + замена ссылок):

```bash
npm run c2b -- ^
  --page "https://gambchamp.atlassian.net/wiki/spaces/BP/pages/197230594/-+." ^
  --recursive ^
  --max-depth 10 ^
  --sync-bookstack ^
  --config bookstack-config.yml
```

### Постоянные соответствия и миграция конфига

`bookstack-config.yml` хранит соответствия Confluence ID → BookStack ID:

```yaml
confluence_base: "https://company.atlassian.net/wiki"
bookstack_base: "https://book.example.com"
books:
  - name: "Payment Systems"
    pages:
      - name: "Payment Systems. BackOffice"
        confluence_id: "256966657"
        bookstack_id: 123
        link: "https://book.example.com/books/payment-systems/page/payment-systems"
```

`bookstack_id: 123` выше — пример, нужен ID реальной существующей страницы.
Группы `books` служат для организации конфига и не перемещают страницы.
Заголовок BookStack берётся из Confluence (`--title` по-прежнему может переопределить
его у исходной страницы). Изменение названия, slug или книги не меняет соответствие.
Разные документы с одинаковыми заголовками поддерживаются при указанных ID.
Повторение одного Confluence ID или одного BookStack ID в конфиге запрещено.

Для существующего конфига выполните сначала проверку, затем миграцию:

```bash
npm run c2b -- --migrate-config --dry-run
npm run c2b -- --migrate-config
```

Укажите `CONFLUENCE_BASE` и токены в `.env`; `BOOKSTACK_BASE` можно получить из
существующих ссылок. Миграция читает оба API и изменяет только локальный конфиг.
Названия сравниваются без учёта регистра, но ID назначаются только после
однозначного совпадения среди доступных API страниц. Неоднозначные названия и
устаревшие URL выводятся как `unresolved` (код выхода 2); для них укажите ID явно.
Миграция не подбирает похожие названия и не создаёт страницы. Остальные проверенные
соответствия сохраняются. Обычная синхронизация также умеет закрепить ID для
встреченных старых записей с однозначным совпадением названия.

Перед любой записью в BookStack синк проверяет все нужные соответствия, в том
числе цели ссылок, не входящие в выгрузку. Ошибка чтения настроенной цели прерывает
проверку до очистки галерей. Страницы без записи в конфиге по-прежнему пропускаются,
а неразрешённые ссылки Confluence превращаются в текст с предупреждением.
Доступность чтения не гарантирует доступность записи: ошибка PUT оставляет
результаты предыдущих страниц; повторный запуск использует уже сохранённые ID.

Межстраничные ссылки формируются через `/link/<bookstack_id>`, а не через `link`.
При синхронизации `name` и `link` автоматически актуализируются для проверенных
документов; ID сохраняются до первого обновления, URL — после каждого успешного
сохранения. Это обновление при запуске, не фоновое расписание. Внешние ссылки и
старые ссылки на страницах, которые не участвуют в синке, массово не переписываются.

Автосохранение сохраняет комментарии, порядок и дополнительные поля блочного
YAML; исходник до первого автосохранения остаётся в `<config>.bak`. Файл заменяется
атомарно, параллельное редактирование обнаруживается. Одновременные синки/миграции
одного конфига блокируются `<config>.sync.lock`. При следующем запуске утилита
проверяет PID и автоматически снимает блокировку завершённого процесса.
Блокировка работающего процесса сохраняется. Базы серверов закрепляются в конфиге, чтобы ID случайно не
применились к другому BookStack/Confluence.

Проверить полный план синхронизации без изменений BookStack и конфига:

```bash
npm run c2b -- --page 256966657 --sync-bookstack --recursive --dry-run
```

HTML-файлы при такой проверке всё равно выгружаются локально.

### Якоря и изображения

При синхронизации исходные якоря получают детерминированные ID `bkmrk-cf-…`,
которые сохраняет HTML-форматтер BookStack. Внутренние ссылки на блоки используют
эти ID, и ответ API проверяется после сохранения. Регистр исходного якоря значим.
Для цели вне текущей выгрузки используются только якоря, подтверждённые её
сохранённым HTML. Если блок не подтверждён, выводится предупреждение, а ссылка
ведёт на начало страницы. Для установки стабильных якорей на связанных страницах
включите их в синхронизацию через `--recursive` с достаточной глубиной.
При частичном сбое новые якоря на ещё не сохранённых страницах появятся после
успешного повторного запуска. Перенос только в HTML и режим создания страницы
сохраняют прежнюю обработку якорей.

Очистка галереи изображений сохранена: если в документе есть изображения, прежние
изображения его галереи удаляются перед загрузкой новых. Для документа без
изображений очистка не выполняется. Ошибка загрузки изображений прерывает
сохранение HTML этой страницы; уже удалённые изображения автоматически не откатываются.

Проверки алгоритма: `npm test`. Тесты работают с временными конфигами и имитацией API.

## Параметры

- `--page`: URL Confluence или pageId; не требуется с `--migrate-config`.
- `--confluence-base`: база Confluence (если `--page` это pageId).
- `--confluence-user`, `--confluence-token`: можно не указывать, если заданы `CONFLUENCE_USER/CONFLUENCE_TOKEN`.
- `--dry-run`: без записи в BookStack и конфиг; с `--sync-bookstack` проверяет весь план.
- `--out`: сохранить в конкретный файл.
- `--out-dir`: папка, куда сохранять HTML в `--dry-run` режиме (по умолчанию `confluence-export`).
- `--recursive`: дополнительно выгружать страницы Confluence, на которые есть ссылки.
- `--max-depth`: глубина рекурсии.
- `--concurrency`: параллельные скачивания картинок (по умолчанию 4).
- `--max-bytes`: лимит размера одной картинки (по умолчанию 15MB).
- `--keep-ids`: не удалять `id` атрибуты при чистке HTML.
- `--config`: путь к `bookstack-config.yml` (карта Confluence ID → BookStack ID).
- `--migrate-config`: проверить и заполнить ID в локальном конфиге, без изменений BookStack.
- `--sync-bookstack`: экспорт + обновление страниц в BookStack по конфигу, замена ссылок Confluence → BookStack.
